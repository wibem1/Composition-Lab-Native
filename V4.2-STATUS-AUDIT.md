# Windows status lifecycle audit

Unreleased follow-up to 4.2.2. The uploaded diagnostic (9) could not be read because the local execution environment is unavailable. This change does not claim to identify why the reported composition produced no visible score.

Confirmed source defect: SetStatus formats the label while busy is true. RequestAIAsync writes its terminal message before its finally block calls SetBusy(false). That block previously changed only the label color and controls, leaving the literal “KI arbeitet” prefix on a completed request. It also unconditionally removed the red error color.

The label now renders from separate message/error state whenever busy changes. Native Windows tests exercise terminal success, cancellation and failure (including color and button state), and assert the actual existing local Compose-handler test ends without the activity label. Normal chat completion explicitly identifies the chat response and its separate Compose action. No musical request routing, score processing or stored user material changes.

Verification uses the existing complete CI matrix: shared tests on Linux, macOS and Windows, native universal Mac build and AppKit self-test, native Windows build and WinForms self-test. The release workflow is deliberately not triggered. Published reference tags and main remain unchanged. The missing-score issue requires the actual unread diagnostic before a broader repair can be claimed.
