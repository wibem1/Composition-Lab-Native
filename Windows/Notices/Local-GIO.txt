Composition Lab local GIO profile: local-gio-lazy-v1

The Windows LilyPond 2.24.4 runtime retains the official executable, Guile, GLib,
GObject, GModule and gettext files. Only libgio-2.0-0.dll is rebuilt from the same
GLib 2.72.4 source version; its zlib 1.3.2 dependency is provided as zlib1.dll.

Change: do not eagerly call gio_win32_appinfo_init(FALSE) in GIO's DllMain.
GAppInfo entry points continue to initialize on demand. The headless engraver
therefore does not enumerate unrelated installed Windows applications on load.
This changes no score, MIDI, source policy, or network behavior.

GLib source commit: 6ed6303e40d6eaf80f2acfbfbcadbb169d156e9c
Source archive, LGPL license, exact patch, and build script are included here.
Compiler artifact: wibem1/Composition-Lab-Native run 39568896709, commit
b7e8bc4f72a19a7252b42bb57b0d5b562fa1aeac.

Build toolchain: MSYS2 MINGW64; GCC, Meson, Ninja, Python with setuptools,
pkgconf, libffi, PCRE, zlib and gettext. The included build script rebuilds the
library and an otherwise identical control from the pinned source revision.
The GIO export set and all non-system imports are checked against the original
bundle before the two verified DLLs are copied into a package.

This is a tested repair candidate. The user-specific startup timeout has not
been reproduced on the build machines and needs verification on the affected PC.
